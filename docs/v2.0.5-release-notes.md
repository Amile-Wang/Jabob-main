# 捷宝宝 Jabob 2.0.5 Beta 版本发布说明

**重要提示**: 这是一个 **Beta版本**，主要实现新功能但 **不保证其他原有功能的稳定性**。稳定的正式版本将是 **2.0.6版本**。

## 版本概述

Jabob 2.0.5 Beta 版本是一个重大的音频系统重构版本，核心目标是引入 **USB音频支持**，特别是针对 **tianhaoUAC定制硬件平台** 的完整音频解决方案。此版本实现了从传统I2S音频到USB音频的平滑过渡，并优化了整个音频处理链路的性能和稳定性。

## 主要新功能

### 1. USB音频编解码器支持 (核心特性)
- **完整USB音频主机支持**: 集成 `espressif__usb_host_uac` 组件，支持USB Audio Class 1.0/2.0设备
- **麦克风专用模式**: 实现USB麦克风直接回调读取模式，优化实时音频采集性能
- **双工通信支持**: 同时支持USB麦克风输入和USB扬声器输出
- **设备信息显示**: 自动识别并显示连接的USB音频设备信息
- **多采样率自适应**: 支持48kHz、44.1kHz等常见USB音频采样率自动检测和处理

### 2. 硬件平台扩展
- **新增tianhaoUAC面包板类型**: 专门针对捷宝宝定制USB音频硬件的BSP支持
- **硬件抽象层增强**: 扩展Board抽象类以支持USB音频相关GPIO和电源管理

### 3. 音频服务全面优化
- **采样率处理改进**: 增强音频服务的采样率验证、转换和输出控制逻辑
- **缓冲区管理优化**: 重新设计音频缓冲区配置，提高内存使用效率
- **性能调优**: 调整音频编解码配置参数，优化CPU使用率和延迟表现
- **日志系统完善**: 为各音频模块补充详细日志，便于调试和问题定位

## 问题修复

### 关键修复
- **互斥锁崩溃修复**: 修复音频重采样日志导致的互斥锁崩溃问题
- **空读防护**: 添加延时机制防止音频数据频繁空读导致的系统不稳定
- **AFE处理器停止逻辑**: 优化音频处理器停止时的缓冲区清理，解决"Ringbuffer of AFE is empty"警告

### 稳定性改进
- **Opus帧长标准化**: 将OPUS_FRAME_DURATION_MS调整为标准的60ms，确保服务器兼容性
- **状态机数据流修复**: 修复speaking状态下AFE处理器停止时的数据流管理问题

## 技术架构变更

### 音频数据流重构
```
传统I2S流程: I2S Codec → AudioService → Opus Encoder → Server
USB音频流程: USB Host → USB Audio Codec → AudioService → Opus Encoder → Server
```

### 配置选项更新
- 新增USB音频相关Kconfig选项
- 更新音频处理相关的默认配置参数
- 调整内存分配策略以适应USB音频缓冲需求

## 已知限制与注意事项

### Beta版本限制
1. **稳定性风险**: 由于是Beta版本，部分原有功能（如传统I2S音频、某些显示功能）可能存在兼容性问题
2. **硬件依赖**: USB音频功能仅在支持USB OTG的ESP32S3开发板上可用
3. **性能影响**: USB音频处理可能占用更多CPU资源，影响其他任务性能

### 使用建议
- **测试环境**: 建议仅在测试环境中使用此Beta版本
- **回退方案**: 如遇严重问题，可回退到2.0.4稳定版本
- **反馈渠道**: 发现问题请及时提交Issue或联系开发者

## 升级指南

### 硬件要求
- ESP32S3开发板必须支持USB OTG功能
- 推荐使用tianhaoUAC定制硬件平台

### 软件配置
1. 在`menuconfig`中启用USB音频支持:
   ```
   Component config → USB Host → USB Host UAC Support
   ```
2. 选择对应的面包板类型:
   ```
   Board Selection → bread-compact-wifi-lcd-tianhao
   ```
