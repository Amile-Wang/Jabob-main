    • 二、Hardwise 平台解读

    Hardwise 是声研科技推出的 AI Agent × 嵌入式硬件研发工具平台。结合其华为海思生态背景，推测该平台最初服务于其自身的星闪音频模组研发（芯片调试、音频测试），后产品化对外提供。

    2.1 三层架构

    层级内容
    ------------
    **AI 层**DashScope API（阿里云百炼，可承载 DeepSeek 等）+ 私有知识库 RAG
    **工具层**插件市场：芯片调试器（DAPLink/J-Link/ST-Link/OpenOCD 等）+ 测试仪器（示波器/万用表/音频分析仪等）
    **硬件层**开发板、芯片 SDK、真实测试仪器

    2.2 关键功能（基于展会 Demo 截图）

    1. Agent 智能体 — Chat 界面对话，可操控硬件（烧录、调试、读仪器数据）

    2. 插件市场 — 仪器驱动标准化，一键安装。已支持 Rigol/Tektronix 示波器、Fluke 万用表、Agilent 信号发生器、音频分析仪 ABTEC-45（I2S/HDMI/ADC/DAC）

    3. 芯片工具链 — 内置主流调试烧录工具（DAPLink/J-Link/ST-Link/OpenOCD/PyOCD/ESP-Prog）

    4. 私有知识库 — 导入 Datasheet/SDK/测试规范后做 RAG 检索

    5. MCP 协议 — 支持 Model Context Protocol 标准化工具集成

    6. 多模式 — 标准 / 慢思(推理增强) / 沙箱 / 编译 / 烧录

    2.3 与我们音频研发的关联

    典型闭环：

    芯片 Datasheet + 测试规范 → 导入知识库 → Agent 生成脚本 → 音频分析仪自动采集 → AI 分析结果 → 推荐调试方案

    三、启发与思考

    维度要点
    ------------
    **AI + 硬件闭环**"AI 直接操控仪器"已验证可行，音频测试的 Agent 化值得探索
    **插件化设备接入**仪器驱动做成可下载插件，降低集成成本
    **RAG + 私有知识库**内部音频标准、芯片文档喂给 AI，可大幅提升问题诊断效率
    **MCP 标准**如考虑自建，MCP 是值得参考的工具集成规范
    **国产替代背景**声研科技深耕星闪音频模组，在华为生态中有真实落地场景，Hardwise 与其主业高度协同

    待验证

  • 产品成熟度（现场 Agent 出现"失联"）
  • 阿里云 DashScope 的海外可用性
  • 音频测试的专业深度（目前仅一个音频分析仪插件）
  • Hardwise 作为独立产品的长期投入意愿

    • 四、建议后续计划

    Step 1 — 安排完整 Demo（2-3周内）

    针对我方真实音频测试场景，要求演示完整链路（需求 → 脚本 → 仪器执行 → 结果分析），接入我方常用芯片平台和设备。

    Step 2 — 内部并行探索（同步）

    R&D 团队跑 PoC：AI Agent + 仪器控制的开源方案，MCP 协议作为工具链统一抽象，大模型在音频场景的表现评估。2-3 周出对比结论。

    Step 3 — 决策（Demo 后 1 周）

  • A：采用 Hardwise + 定制合作
  • B：借鉴架构，自主开发
  • 观望：暂不成熟，内部方案先行

    • 五、小结

    声研科技不是普通的 AI 工具创业公司——它是一家深耕华为海思生态、参与星闪国家标准制定的音频硬件企业，Hardwise 是其内部研发能力的外溢产品。对我们而言，核心问题是买还是建：建议以 Demo + 内部 PoC 双轨并行，用数据驱动决策。
